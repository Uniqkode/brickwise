Bring the inspection together.

Bring inspection photos, thermal images and technician notes together under a building, asset and visit reference. Retain the original source so every observation can be traced.

THE AI WORKLOAD

Read the evidence.
Keep the context.

An inspection is a collection of related sources. Useful analysis connects what is visible, what the technician recorded and which asset needs a decision.

01 / SOURCE READING

Images and documents, together.

Visual analysis describes the condition in an inspection image. Document extraction turns inspection forms, service sheets and scanned records into usable text and fields.

How it fits +

The Azure design uses Document Intelligence for text, tables and form fields, and a vision-capable Azure OpenAI model for image observations. A thermal image is reviewed with its supplied context; an image alone does not establish an engineering cause.

02 / ASSET CONTEXT

Find the right supporting record.

Building, asset, visit and source references keep similar observations connected. Retrieval can bring the relevant maintenance manual and earlier service record into the same review.

How it fits +

Azure AI Search provides the planned retrieval layer. Organization and asset filters must be applied before supporting passages reach the model. Each retrieved passage keeps its source reference so a reviewer can inspect it.

03 / STRUCTURED OUTPUT

Turn observations into a brief.

The analysis contract produces a title, summary and source-linked findings with a review priority, supporting observation and proposed action. Evidence checks and reviewer notes stay with the handover.

How it fits +

The existing service adapter validates the report structure, checks source references and rejects text quotes that do not appear in their cited source. The review desk requires every finding to be checked before its brief can be queued.

REQUEST & BATCH DESIGN

The current analysis adapter accepts up to 8 source inputs, including at most 4 images of 2 MB each and 90,000 characters of combined text. A response contains up to 8 findings.

Portfolio ingestion would split a larger inspection pack into asset-level jobs, process bounded batches and assemble the results for review. Repeated requests can reuse a recent result rather than repeat the same model call.

DEPLOYMENT ARCHITECTURE

Infrastructure built for
building inspection workloads.

The Azure services below define the architecture Brickwise is being built toward. The public website remains on GitHub Pages; the Azure OpenAI adapter is implemented, while the wider service integrations are build milestones.

01 / APP & API

Serve the workspace and its jobs.

Azure Static Web Apps is the target option for application delivery. Azure Container Apps would host the Node analysis API and background workers, with scaling tied to requests and queued work.

How it fits +

Keep the user interface separate from model processing. The browser submits an authorized inspection job; server-side workers call the selected model and return the result. Provider credentials stay on the server.

02 / EVIDENCE & RECORDS

Retain the source and the result.

Azure Blob Storage would hold original photos, extracted documents and report files. Azure SQL Database would hold organizations, buildings, assets, findings, assignments and review events.

How it fits +

The design uses organization-scoped storage containers and tenant-keyed records, with access checks at both the API and data layer. Source versions remain associated with the report that used them.

03 / DOCUMENTS & LANGUAGE

Read records. Draft the action.

Azure Document Intelligence would extract text, tables and fields from inspection forms and service records. Azure OpenAI would combine image observations and technician notes into a structured, cited repair brief.

How it fits +

The Azure OpenAI connector already supports image and text evidence. Document ingestion is a separate integration milestone. Human approval remains part of the workflow for every proposed maintenance action.

04 / RETRIEVAL

Bring asset knowledge into view.

Azure AI Search, now part of Foundry IQ, would index approved manuals, earlier inspections and maintenance history so the analysis can use relevant supporting passages.

How it fits +

Retrieval is scoped to the organization and asset. The report keeps the original source references rather than treating a generated summary as a replacement for its evidence.

05 / JOB ORCHESTRATION

Keep large inspection packs moving.

Azure Service Bus would queue inspection jobs and separate upload bursts from model processing. Workers can retry failed jobs, route persistent failures for review and avoid issuing duplicate work for the same request.

How it fits +

Queue depth and job age guide worker scaling. Per-organization limits and model quotas control concurrency so a large portfolio upload does not block every other team.

06 / SPECIALIST VISION

Add trained models where they help.

Azure Machine Learning is the planned route for evaluating and running specialist defect models over image batches. Azure Kubernetes Service GPU workers are an option for sustained, self-hosted vision inference.

How it fits +

Begin with labelled inspection evidence and technician-reviewed evaluation. Add dedicated GPU workers when measured model demand justifies them. Managed Azure OpenAI calls run on the managed service, separately from these GPU workers.

07 / IDENTITY & SECRETS

Give each role the right access.

Microsoft Entra ID would provide organizational sign-in. Role-based access separates facility managers, reviewers and technicians. Managed identities and Azure Key Vault keep service credentials and keys out of the browser.

How it fits +

Authorization must follow the organization, building and asset for each request. Workload identities receive only the storage, queue, database and model permissions their jobs require.

08 / NETWORK & PROTECTION

Protect the evidence path.

The deployment design uses HTTPS with TLS 1.2 or later, encryption at rest and Azure Private Link for supported storage and AI resources. Customer-managed keys can be considered where supported and required.

How it fits +

Private endpoints and access policies are configured for the selected services and deployment region. Retention, data location and customer key requirements are agreed before connecting organizational evidence.

09 / OPERATIONS & AUDIT

Make the workload observable.

Azure Monitor and Application Insights would track request latency, queue age, failures and model usage. Microsoft Defender for Cloud would support security posture monitoring. Review events retain the actor, source version and decision.

How it fits +

Approved report snapshots can use Azure Blob immutable retention policies where a retention requirement calls for them. Operational telemetry and immutable records are separate controls; they are configured and verified during deployment.

WHY THIS WORKLOAD SCALES

One visit can produce many image observations, document pages and follow-up records. Portfolio review adds parallel model jobs, evidence storage, retrieval, retries and a review history, rather than a single text-generation request.

Start with the core API, storage, queue and organizational access. Add retrieval, specialist model training and GPU capacity as the evidence set and measured demand grow.
