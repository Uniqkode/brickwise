DATA HANDLING POLICY

Your data.
A clear handling policy.

Brickwise · Updated 14 November 2026. This policy describes the implementation delivered with the MVP and the boundaries of an optional configured AI service.

Current storage

Sample register changes, retained reports and pilot drafts are stored under brand-specific keys in this browser. Demo access uses sessionStorage. They are not shared between operators or backed up by this static website.

Connected analysis

Only the connected-analysis action transmits entered text and selected images to the service address you configure. Its server then calls the configured AI provider. Review that provider’s account, region, agreement and retention settings before using real organizational data.

Server-side credentials

Provider keys and Azure authentication tokens belong in the server environment. They are never placed in the website’s public JavaScript. A service token used by the connected form is held for the request and is not saved in report history.

Temporary server cache

The optional adapter caches a limited number of identical review results in memory for ten minutes. Reports may contain quoted input text. The cache is not a production evidence archive.

Retention and deletion

Reset demo data clears this brand’s local records, drafts, accepted reports and session in the current browser. It does not remove downloaded files or data already submitted to a separately configured service.

Proposed Azure storage

Azure Blob Storage and the other components on the technology page describe the intended production data path. No Azure storage deployment, regional data residency or backup arrangement is claimed until it is configured and verified.

Before a real-data pilot

Define organization access, permitted data categories, retention, deletion, backups and incident responsibilities. Publish the actual operating company and private contact channel before accepting confidential or personal operational data.
